# Codex Inline Stats

Windows 上的 Codex 桌面端内嵌统计栏：在聊天输入框下方显示处理阶段、最近调用均速、累计 token、缓存命中率和整段聊天当前有效上下文的估计占比；达到 70% 时提示准备新会话交接。

**v0.4.0 新增外置窗口**：手动启动独立原生窗口，直接读取本机 Codex 会话数据库与日志，无调试连接、无网络端口。Codex 可从任意原版入口启动或重启。

**非官方本机定制。** 使用 localhost 调试连接向页面加入 DOM，未修改 Codex 的签名安装文件。界面占据正常布局空间，随聊天切换重新挂载，不使用悬浮窗口。

## 环境

- Windows 10/11，Windows PowerShell 5.1 或 PowerShell 7。
- 通过 MSIX/Microsoft Store 安装的 Codex。当前验证版本：`26.1002.7124.0`。其他安装布局尚未验证。
- [Node.js](https://nodejs.org/) 22+ 和 [Python](https://www.python.org/downloads/windows/) 3.10+，加入 PATH。只使用标准库，无 npm/pip 依赖。

## 安装与启动

### 手动启动的外置应用

Python 需带标准库 `tkinter`（python.org 的 Windows 安装通常包含；部分嵌入式 Python 不包含）。执行：

```powershell
.\Install.ps1 -External
```

安装后自行双击桌面 **Codex 外置统计**，关闭窗口即停止该窗口的采集；不自动随 Codex 或登录启动。仍使用原版 Codex。`-External` 会停止此安装目录的旧内嵌采集器，移除指向它的内嵌桌面入口和登录启动入口，创建外置入口；不会退出 Codex或删除聊天。正在运行的旧页面栏位可能保留到 Codex 页面销毁。

通过搜索标题或完整会话 ID，再从列表选择要监测的会话。标题重复时可用 ID 区分，选择后不会自动跟随其它聊天。外置窗口不读取 Codex UI，因此不知道你当前打开的聊天；首次默认选择最近更新的一项，此后保存所选 ID。列表来自数据库最近 512 个聊天；保存的更旧会话仍可读，但列表不一定包含它。

窗口采用参考 Token Monitor 的窄竖向深色设计：大号等宽累计数值、青色上下文条、分区细线及独立会话列表，保留 Windows 原生标题栏。可显示调用均速、累计 token、缓存命中率、最近上报的有效上下文、上报时间和处理阶段，也可手动置顶；上下文达到 70% 时可复制交接指令或暂不提醒。把指令粘贴到**所选的原会话**发送。原生进度条视觉长度封顶 100%，文字读数保留超过 100% 的数值。所有统计口径仍遵循下文；不提供服务端逐 token 速度。更新可能有日志交付延迟，且 Codex 数据库/日志格式变化仍可能需要适配。

外置偏好保存在 `%LOCALAPPDATA%\CodexExternalStats\preferences.json`，只保存所选 ID 和提醒选择，不保存聊天内容。外置模式安装与运行均不需要 Node.js。升级前先关闭外置窗口，再重新执行 `Install.ps1 -External`；安装脚本不会自动关闭正在运行的外置窗口。

外置模式运行 `Get-Status.ps1` 会报告 `mode=external`、`debugRequired=false` 和是否存在窗口进程；进程存在不能单独证明读数正确。无需排查内嵌模式的调试端口。

### 紧凑悬浮窗

v0.5.0 点击面板底部 **悬浮窗 ↗**（或 Ctrl+F），将完整面板收起为无系统标题栏的小窗，默认置顶；只显示所选会话标题、处理状态、调用均速、上下文占比、累计用量和缓存。直接拖动标题或数值区域移动。点击 **↗**、双击文字区域或按 Esc 返回完整面板。

点击 **⋯** 或右键文字区域，可切换始终置顶、100% / 96% / 85% / 70% 透明度、复制交接指令、暂不提醒或退出统计。70% 提醒出现时悬浮窗增加交接按钮，降至阈值以下或被关闭后恢复紧凑高度。不模拟点击穿透，避免无法操作或误点底层应用。位置、透明度、置顶和是否使用悬浮模式保存到外置偏好；退出后下次手动启动会恢复。

当前悬浮窗限于主屏幕范围，启动时会把旧位置收回可见区域，防止显示器变化后找不到窗口。完整面板仍可通过 Windows 标题栏移动到其它显示器。透明度是整窗透明，不是 Token Monitor 的背景磨砂效果。

### 内嵌模式

下载 Release 中的 ZIP 或本仓库源码，完整解压，进入该文件夹执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Install.ps1
```

安装到 `%LOCALAPPDATA%\Programs\CodexInlineStats`，创建桌面入口 **Codex（内置统计）**。从菜单完全退出 Codex，再使用该入口启动；单独关闭窗口可能仍留下后台进程。原有聊天正在执行时，先等待任务结束。

正常使用只需此入口，它会一起启动采集器。原版入口启动的新进程不会启用统计。安装器不会自动退出或重启 Codex。

v0.3.2 的入口会检查实际统计连接。如果 Codex 已在运行但未启用连接，会显示提示，不再静默退出。选择确定后，在 10 分钟内从菜单完全退出 Codex，启动器会等待旧进程结束再自动打开；不会强制结束进程或中断任务。重复点击入口不会创建多个等待启动器。新启动后会在最多 30 秒内检查调试页面，失败会显示提示。`Launch.ps1 -WaitForExit` 直接启用等待；`-NoDialogs` 适用于诊断和测试，不显示弹窗。

运行环境未加入 PATH 时，可显式指定路径：

```powershell
.\Install.ps1 -NodePath 'C:\path\to\node.exe' -PythonPath 'C:\path\to\python.exe'
```

可选：`-StartAtLogin` 启用登录后后台采集；它不会启动 Codex。`-Port 9335` 指定本机端口；`-InstallDir` 指定安装目录；`-NoShortcuts` 不创建快捷方式；`-CheckOnly` 只检查环境，不安装。端口冲突时请选择其他端口，并完全退出后从新入口启动。

v0.5.1 切回内嵌模式时会停用对应外置进程、移除外置桌面入口，并在桌面和开始菜单创建统计入口。可选 `Install.ps1 -RepairShortcuts` 将当前用户桌面、开始菜单和任务栏中直接指向已安装 Codex 可执行文件的快捷方式改为统计启动器；原文件备份到安装目录的 `shortcut-backups/`，路径记录在 `shortcut-backups.json`。不改变其它应用的入口，也不改变 MSIX 或协议注册。运行 `RepairShortcuts.ps1 -Restore` 可恢复仍指向本启动器的入口；卸载或切换外置时也会恢复。更新 Codex 可能重建原版入口，Windows 任务栏还可能缓存激活信息，修复快捷方式不等于所有启动路径都经过启动器。

内嵌采集器会在读取子进程退出或超时后自动重建它，断线后继续探测本机 IPv4/IPv6 并重新注入。统计栏 15 秒没有收到有效更新时清除旧数值，显示“统计连接等待恢复”；重新连接后恢复数据。页面布局/日志格式变化、Node 主进程退出、以无调试参数的原版进程重新启动等情况仍可能需要启动器或人工排查；不会自动强制重启 Codex。

v0.5.2 将当前 Codex 图标保存为安装目录的 `codex.ico`，统计快捷方式不再引用带版本号的 WindowsApps 路径，避免客户端更新后图标丢失。图标只在本机安装时从已安装 Codex 提取，不随源码或 Release 分发。修复已有入口可运行 `UpdateIcon.ps1` 后执行 `RepairShortcuts.ps1`，不需要停止采集器或 Codex。

## 统计口径

| 指标 | 含义与限制 |
| --- | --- |
| 生成中 / 工具运行中 / 最近响应 | 依据日志事件判断的处理阶段，可能有交付延迟。 |
| 调用均速 | 最近已完成响应的输出 token（含推理，不重复相加）÷ 客户端观察到的调用间隔。包含排队、首 token 等待、网络及日志交付开销；从已知工具全部返回后重新计时。不是实时逐 token 速度，也不是服务端解码 TPS。 |
| 累计 token | 日志的累计 token 计数，可能在每次调用中重复包含上下文输入；不代表订阅账单或唯一上下文长度。 |
| 缓存命中 | 最近一次调用的缓存输入 token ÷ 全部输入 token。 |
| 对话上下文约 X% · X / Y tok | 最近上报的 `last_token_usage.total_tokens` ÷ `model_context_window`。反映整段聊天当时仍在使用的有效上下文估计，包含保留历史、指令及工具信息；不是最后一轮输入，也不是所有历史原文的累计 token。窗口取会话报告，不按模型名猜测。 |

没有可靠计时边界时显示 `--`，过旧数据也不显示速度。新一轮尚未完成调用时不沿用上一轮速度。没有硬编码 50 tok/s 上限。

上下文会在下一条 `token_count` 记录到达时更新。压缩、回滚或模型改变后清除旧读数，显示“等待新记录”，然后采用新的窗口和计数。特别是压缩后，日志可能报告输入/输出为 0、但 `total_tokens` 为非零的重新估算值；这里保留该上下文读数。缺少容量或计数时不猜测百分比，上报超过容量时也不悄悄封顶。最近添加的用户/工具内容可能尚未被计入，因此不能保证每一刻精确。Codex 原生 UI 可能采用额外基线调整，百分比不一定相同。

旧算法曾使用最后一条 reasoning/message 的交付时间作为整次响应起点，导致上百甚至上千 tok/s 的虚高读数。此版本修正为完整响应的观察间隔。原始日志缺少完整的服务端时序，因此无法精确还原官方生成 TPS。

## 上下文交接提醒

当前会话最近上报的有效上下文达到 **70% 或以上**，统计栏下方显示“建议本轮结束后新开会话并交接”。这是提前整理任务的建议，不代表模型必须换会话或上下文已失效；沿用上报的实际窗口，不固定按 1M 计算。缺少有效读数、正在等待压缩后的新记录或占比低于 70% 时不显示提醒。

点击 **复制交接指令**，再粘贴到**原会话**发送。指令要求 Codex 核对实际文件、保存 Markdown 交接说明、列出已完成验证与剩余任务，并新建同项目会话接续执行；无法创建时提供手动启动指令。正在运行的任务和定时自动化只要求列明状态，避免重复执行或重复创建。最终交接与新会话创建由 Codex 执行，插件只复制指令，不生成或验证交接内容。

插件不会自动发送消息、改写输入草稿、停止任务或直接创建会话。复制成功后可关闭提示；选择 **暂不提醒**，该会话在此次超过 70% 期间不再提示。提醒选择按会话保存在本机页面的 localStorage（最多保留最近 200 个会话 ID，不保存聊天内容），切换会话或重启后仍生效。有效读数降至 70% 以下时重新启用，之后再次达到阈值会重新提示。页面存储不可用时仅在当前页面内记住选择。

## 客户端更新后的维护

1. 正常更新 Codex，完全退出后从 **Codex（内置统计）** 启动。脚本自动发现新版 MSIX 安装路径。
2. 切换两个聊天，确认统计跟随聊天且布局正常；完成一次回复，确认数字更新。
3. 不显示时运行诊断：

```powershell
& "$env:LOCALAPPDATA\Programs\CodexInlineStats\Get-Status.ps1"
```

`debugReachable=false` 通常需要完全退出并从专用入口重开，或检查端口冲突；`codexPageFound=false` 可能是页面地址变更。`active` 只证明最近一次注入/更新成功，不证明所有指标口径正确。结合时间戳检查状态是否过旧。

采集器与诊断会探测 IPv4 `127.0.0.1` 和 IPv6 `::1` 两种本机地址。Codex 重启后可能切换调试服务的绑定地址；v0.3.1 修复了只连接 IPv4 导致统计消失的问题。诊断的 `debugAddress` 显示实际可用的地址。

v0.3.2 的 `launch` 字段记录入口最近一次尝试的结果与时间。`blocked_existing_process` 表示旧进程已有但没有可用统计连接；`waiting_for_exit` 表示正在等待退出；`ready` 表示入口已验证调试页面；`debug_unavailable` 表示新启动后连接仍未就绪。没有新启动记录时，不能仅凭当前进程推断用户点击了哪个入口。`ready` 是记录当时的状态，须结合当前 `collector` 与调试连接检查。

插件更新：下载新源码，重新执行 `Install.ps1`（自定义路径或端口应使用原参数），再执行安装目录的 `StartAgent.ps1`。更新会停止该目录的采集器，不会中断 Codex 聊天。没有自动更新、自动适配或自动上传诊断。

若客户端改变 DOM、路由或 React 属性，应检查 `renderer.js`，修改后递增 `version`；若改变日志或状态数据库格式，应检查 `telemetry.py` 和 `reader.py`。避免仅根据数值是否“看起来合理”判断兼容性。

## 安全与隐私

采集器读取本机 Codex 状态数据库和会话日志，以绑定当前聊天和提取用量。它没有云端服务，不上传聊天、日志或统计数据，也不读取账号凭据。源码和 Release 不包含开发者本机日志、配置、账号资料或运行环境二进制。

**调试端口意味着本机其他进程也能访问和控制应用页面。** 启动参数请求绑定 `127.0.0.1`，实际客户端也可能选择 `::1`；采集器只探测这两个本机地址。请勿开放防火墙、代理转发或分享调试连接；实际使用时应检查端口仅监听 loopback。完全退出 Codex 才会关闭它。对调试端口有严格限制的环境不适合使用此方案。

此功能依赖客户端内部结构，不属于稳定官方插件接口。客户端更新可能使统计停止或出现口径变化。

## 停用与卸载

临时停用：运行安装目录中的 `StartAgent.ps1 -StopOnly`，完全退出 Codex，再从原版入口启动。当前已注入的栏位会在页面销毁后消失。

卸载：

```powershell
& "$env:LOCALAPPDATA\Programs\CodexInlineStats\Uninstall.ps1"
```

脚本停止该目录的采集器及 Python reader，移除指向该目录的桌面/登录启动快捷方式。完全退出后从原版入口启动。安装文件保留，可手动删除该目录；不删除 Codex 聊天，不修改 Codex 安装，也不会恢复或启动其他 HUD。

```powershell
python tests/test_telemetry.py

```

渲染测试使用本机 Edge headless 和合成聊天页面；可通过环境变量 `EDGE_PATH` 指定 Edge 可执行文件。测试包含聊天重新挂载、旧响应拒绝、窄布局、上下文读数与等待状态、70% 提醒边界、跨会话与重载后的提醒选择、压缩后重新启用、剪贴板成功/失败及回退、保留草稿、不自动发送、复制过程中切换会话或压缩，以及移除。解析测试覆盖完整响应计时、推理不重复计数、用量去重、并行工具返回、重复通知、边界缺失，以及压缩后上下文重估、模型/窗口变化、回滚和无效记录。

Windows CI 在 Python 3.10 / 3.14 与 Node 22 上运行这些检查。合成页面测试不等于所有真实客户端版本、主题、窗口尺寸和模型的兼容性保证。原型曾通过本机真实日志回放和真实 Codex 内嵌验收；发布版的安装与生命周期脚本另经隔离目录验证，尚无第二台机器实测。

连接测试使用本机临时 HTTP 服务，验证 IPv6 独占监听、两种地址切换、无 Codex 页面、错误/无效响应与非本机调试 URL 拒绝；测试结束后关闭服务。

启动测试使用隔离目录和模拟进程/连接，验证旧进程无调试连接时的状态记录、等待完全退出后启动、参数保留以及已有正常进程的复用。不会为了测试退出真实 Codex；真正退出后的自动重开仍须由用户在任务结束时确认。

外置测试使用原生 Tk 窗口和合成读数，验证同名会话区分、手动选择后旧响应拒绝、提醒持久化、压缩后读数重置、交接复制与最小窗口布局。真实日志读取另行在本机验证，不等同于第二台机器验证。
